# Sideloading the SComm Office Outlook add-in (dev)

Development manifest: `apps/outlook-addin/manifest/manifest.xml`  
Dev server: **https://localhost:5173** (Vite + `@vitejs/plugin-basic-ssl`)

## 1. Start the add-in dev server

```bash
pnpm --filter @scomm-office/outlook-addin dev
```

Visit **https://localhost:5173/taskpane.html** once and accept the browser certificate warning (self-signed).

Optional: start the SComm server on port **8787** for pubkey API calls.

## 2. Trust HTTPS locally

Outlook loads the task pane over HTTPS. If the certificate is untrusted, the pane will fail to load.

- **Browser:** proceed past the warning for `localhost:5173`
- **Windows:** you may need to import/trust the dev cert generated by the basic-ssl plugin, or use Edge/Chrome with the cert accepted in the same profile Outlook uses (web)

## 3. Sideload the manifest

### Outlook on the web

1. Open [Outlook on the web](https://outlook.office.com)
2. Open an email (read or compose)
3. **Settings → View all Outlook settings → Mail → Customize actions → Add-ins** (path may vary by tenant)
4. **My add-ins → Add a custom add-in → Add from file**
5. Select `apps/outlook-addin/manifest/manifest.xml`
6. Confirm sideload

### New Outlook for Windows

1. Open **New Outlook**
2. **Settings → Manage add-ins** (or **Get Add-ins**)
3. **My add-ins → Add a custom add-in → Add from file**
4. Select `manifest/manifest.xml`

### Classic Outlook (Windows)

Use **File → Manage Add-ins** or centralized deployment for production. For dev, **Outlook on the web sideload** is often faster; classic may require registry/Centralized Deployment for event handlers.

## 4. Open the task pane

1. Open a message (read or compose)
2. Ribbon: **SComm** button under the default tab (Message Read / Compose command surface)
3. Task pane loads `https://localhost:5173/taskpane.html`

## 5. Event handlers (optional)

`commands.html` registers stubs via `Office.actions.associate`:

- `onMessageSend` (soft block — not wired to policy yet)
- `onMessageCompose`
- `onMessageDecrypt`

LaunchEvents in the manifest are **commented** until Mailbox 1.12+ runtime is validated for your host. Uncomment and add `<Runtime resid="CommandsUrl" />` per [openspec/microsoft/event-based-activation.md](../openspec/microsoft/event-based-activation.md).

## 6. Troubleshooting

| Symptom | Check |
|---------|--------|
| Blank task pane | Dev server running? Cert trusted? CSP blocking? |
| Add-in not in ribbon | Manifest sideloaded? Message item (not calendar)? |
| Pubkey errors | Server on `http://localhost:8787`? CORS? |
| IDR blocked | CSP `connect-src` includes your IDR host; WebRTC support |
| Icons 404 | Add PNGs under `apps/outlook-addin/public/assets/` |

## 7. Browser-only dev (no Outlook)

Open **https://localhost:5173/taskpane.html** — uses **MockMailHost** with the `simple` testkit fixture and shows a **Mock host** banner.
